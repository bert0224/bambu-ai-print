# 拓竹工程型 3MF：兼容性与保留盘检查

仅用于生成或修改含拓竹工艺、多盘与对象设置的工程 3MF。几何型 3MF 不能冒充完整工程。

## 已复现的兼容性陷阱

在 Bambu Studio `v02.08.02.61` 的导入路径中，Expat 使用 `XML_ParserCreate(nullptr)`，关系回调直接比较原始标签名 `Relationship`。ElementTree 将默认命名空间自动序列化为 `ns0:Relationship` 时，通用 XML 仍然有效，但该分支不会发现子模型，随后可能产生空对象/无几何错误。不能仅做命名空间感知的 XML 引用检查。

- 对 `_rels/.rels` 和模型关系文件，保留无前缀的 `Relationships` / `Relationship`，使用根元素默认 `xmlns`。不要全局替换 ZIP 中的 `ns0` 字符串。
- 同样核查模型核心标签及 `p:path`、`p:UUID` 的字面前缀。序列化完成后再检查实际输出，不能只看内存中的 XML 树。
- 不改全局 ElementTree 命名空间注册来修一个关系文件，以免后续模型文件被序列化成另一套前缀。可用无前缀标签构造独立关系树并显式设置默认 `xmlns`。
- 这是一个已验证版本的兼容性约束，不宣称所有版本都如此。目标切片器更换时仍需实际导入确认。

最小只读检查：

```powershell
python scripts/check_bambu_project.py 新工程.3mf --baseline 原工程.3mf --preserve-plate 1
python -m unittest discover -s scripts -p test_bambu_project.py
```

检查脚本覆盖关系回调语义、依赖可达性、非空网格和指定盘保留项。它不调用切片器、不验证网格流形、完整配置 schema、射频、强度或打印结果；不能单独授予 L1/L2。遇到不支持的封装结构应报错并检查，不修改文件或静默降级。

## 修改既有工程的交付门禁

1. 保存输入哈希、修改盘号和允许改动的对象 ID。先列出每盘已有零件及数量，识别旧版夹头、共享资源和原有摆放问题。只改第二盘时，不直接改第一盘共用的网格。
2. 为新零件使用独立资源和对象标识。核对 `build`、组件、盘实例、对象/部件配置、装配记录及关系文件一致。旧缩略图、拾取缓存不得继续表示新几何。
3. 对保留盘比较实际网格字节/哈希、组件引用、实例变换、缩放、盘成员、对象配置、装配记录和全局工艺。分别报告几何、摆放、配置是否变化，不把“原网格没变”扩大为“什么都没变”。
4. **保留盘也要检查摆放。** 在构建变换后的打印坐标下检查所有实际实例：重复份数、盘归属、模型相交、落板、超边界，以及 brim/支撑/逐件打印安全间距。包围盒相交仅是候选警告，不等于实体碰撞；使用精确投影/网格检查或真实切片器确认。
5. “沿用原文件”不能替代排布验收。原盘已有重叠时，说明对象 ID、证据和影响；未获排版变更授权时保留并提示，不静默重新排布、删件或给出整盘可打印结论。新夹头留在指定盘，避免用户误打旧夹头。
6. 保存后通过独立回读核验。获取允许的软件访问后，在真实 Bambu Studio 中打开交付文件，检查所有盘的实际对象数量、外观、摆放和工艺，再切片检查。不能用缩略图、静态解析或源码推断声称已导入/已切片。
7. 若缺少软件访问，只交付注明“未实际导入/未切片”的候选，并提供独立 STL/STEP 退路；不要要求用户忽略配置无效、零体积或无几何警告。

## 必保留的回归用例

- 默认命名空间的关系文件可发现子模型；`ns0:Relationship` 变体必须被拦截。
- 缺失子文件、缺失组件目标、零三角面、改变保留盘摆放或共享网格必须被拦截。
- 本次真实失败文件应失败，修正版及原始基线应通过结构检查；不能只测合成数据。
- 新增摆放检查需用“重叠实例”和“仅包围盒重叠但模型分离”区分粗筛与最终结论，避免将不精确检查包装成验证通过。

## 打印后变形反馈

收到“底座翘起、滑轨变形、滑块卡住”时，先核对用户实际打印版本、重新排布后的工程/G-code及对应几何与工艺。模型一致只能排除本轮 CAD 修改，不能排除原设计公差、切片改变或制造变形。夹头适配反馈仅确认该夹头与该 PCB 的配合，不自动确认底座稳定性、滑轨功能或全部 L5/L6。未取得照片、卡点位置和必要尺寸前，不建议强推、随意打磨或凭空调整温度/缩放。
